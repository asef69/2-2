===== page 2 =====
Why Requirement Analysis Matters
Poor Requirement analysis is one of the major reasons 
of Project Failure  
●Misaligned Features: Teams build the wrong or
misaligned features. This often causes total
rewrites.
●Architectural Churn: Constant changes break
code structure, leads to bugs and often
hampers architectures in the mid-way.
●Resource Drain: Mid-flight revisions cause
missed deadlines, budget overruns, and team
burnout.
Cost Reduction
Fixing errors early costs much less than post-
release hotfixes.
Stakeholder Alignment
Establishes a single source of truth across 
product teams.

===== page 7 =====
TAXONOMY
Functional vs. Non-Functional Requirements
What the system MUST DO
How WELL the system performs
Functional 
Send money, check balance, cash-in via agent, 
view transaction history.
Non-Functional 
Works offline, loads in 3 s on 3G, usable by 
low-literacy users, audit logging.

===== page 9 =====
Prioritization Framework
Need to prioritize some requirements over others. Cannot do all or do all at the same time or give equal importance to all.
MUST HAVE
Non-negotiable core functionality required for release.
SHOULD HAVE
High-value features with viable workarounds if omitted.
COULD HAVE
Desirable enhancements included only if resources permit.
WON'T HAVE
Out of scope for current development cycle.
The MoSCoW Method
Many other methods also exist.
