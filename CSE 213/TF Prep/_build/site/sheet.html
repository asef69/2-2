Testing formulas and rules

Cyclomatic complexity V(G) = E − N + 2 = P + 1 = number of regions. It equals the number of basis paths and the minimum number of test cases for branch coverage.

TechniqueRule
Equivalence partitioningsplit each input into valid and invalid classes; one test per class
BVA for [a, b]a−1, a, a+1, b−1, b, b+1 (add a nominal value)
Weak / strong ECTweak = largest number of classes of any one input; strong = product of the class counts
Statement / branch coverageevery statement runs / every decision takes both outcomes. Branch coverage subsumes statement coverage
Condition coverageevery atomic condition takes true and false. Remember short-circuit evaluation in || and &&
Loop tests0, 1, 2, m, n−1, n, n+1 passes
Integrationtop-down needs stubs, bottom-up needs drivers
Verification vs validationbuilt the product right / built the right product

Refactoring and unit testing

  • Refactoring changes structure, not behaviour. Run the tests before and after every small step.
  • Smells to name: long method, large class, duplicate code, feature envy, shotgun surgery, divergent change, data clumps, primitive obsession, switch statements, refused bequest.
  • Fixes to name: extract method, move method, extract class, replace conditional with polymorphism, introduce parameter object, pull up method.
  • JUnit: @Before/@After run around each test, @BeforeClass/@AfterClass once, assertEquals(expected, actual). TDD cycle: red, green, refactor.
